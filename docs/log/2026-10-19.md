## 19 October 2026

Objective: Add a boot banner to NODE_A: node name, firmware version and reset reason.

What I did:
- Created firmware/node_b by copying node_a and changing the node name to NODE_B
- Moved the constants for node name (NODE_A) and firmware version (v0.1.0)
  to the top of main.cpp.
- Built the banner line from several Serial.print() calls ending with println().
- Added the reset reason using esp_reset_reason().
- Set up a VS Code workspace with the repository and firmware/node_a,
  so PlatformIO works while the whole project stays visible.
- Created the PlatformIO project firmware/node_b.
- Recorded the reset reason and the upload procedure in Hardware.md.

Result: After start-up the ESP32 prints the banner with node name, firmware
version and reset reason. After power-on the reset reason is 1
(ESP_RST_POWERON, "Vbat power on reset").

Errors and fixes:
1. "+" between const char* texts does not concatenate - it is a compile error.
   Fix: print the parts one by one with Serial.print().
2. esp_reset_reason_t() always returned 0 - it is the type, not the function.
   Fix: call esp_reset_reason().
3. Opening firmware/node_a alone hid the rest of the repository.
   Fix: multi-root workspace (repository + node_a).
4. Upload still requires holding BOOT. Handbook 15.3 lists this as the procedure
   when the board does not enter upload mode on its own. Noted in Hardware.md.

Next test: Check the reset reason after pressing EN, then mini-exercise 2:
a counter printed every second with millis(), without delay().

Conclusion: Constants used in the whole program belong at the top of the file.
Read the documentation carefully - a type and a function can have almost the same name.

What I learnt:
- The boot banner identifies the board, the firmware and why it started.
- A node is a single device in the network: NODE_A simulates the drone,
  NODE_B the ground station.
- The firmware version is a label I set myself (v0.1.0) and record in CHANGELOG.
- Constants declared inside setup() are local; at the top of the file
  they are global and visible in loop() too.
- const char* is an address in memory, so "+" cannot join two texts.
- print() stays on the same line; println() ends the line.
- Several print() calls do not copy the text in RAM; String concatenation
  uses the heap. Serial.printf() is a one-call alternative.
- A name ending in _t in Espressif docs is a type; the function has a similar name.
- esp_reset_reason() returns an enum; printed as a number, its meaning is in the docs.
- Reset reason 1 = power-on reset.
- VS Code can open several folders in one workspace.

What I don't know yet:

- How to use Serial.printf() format specifiers.
